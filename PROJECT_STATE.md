# ЭРА — паспорт текущего состояния

Дата: 2026-08-01

## Цель проекта

Эра — системный Android-ассистент, который со временем должен стать общей точкой взаимодействия с ИИ и инструментами пользователя.

Основная идея:
пользователь → Эра → ИИ / локальные инструменты / приложения → действие → результат.

Проект разрабатывается непосредственно на Android-смартфоне.

---

## Устройство и среда

- Android 16
- HiOS 16.2
- Разработкав Android IDE
- Kotlin
- Package: com.era.assistant
- Gradle 6.1.1

## Что уже работает

### ChatGPT

Эра умеет:

- запускать официальное приложение ChatGPT;
- передавать текст через Android ACTION_SEND;
- использовать AccessibilityService;
- находить кнопку отправки ChatGPT;
- автоматически отправлять переданный текст.

Этот механизм экспериментальный и зависит от интерфейса ChatGPT.

## Системный Android Assistant

Эра зарегистрирована как системный цифровой помощник.

Android показывает Эру в списке:

Настройки → Цифровой помощник по умолчанию.

Эру удалось выбрать помощником по умолчанию.

Создан:

EraVoiceInteractionService

Подтверждено событие:

onReady

Это означает, что Android действительно запускает VoiceInteractionService Эры.

## Эксперимент с заблокированным экраном

Цель:

понять, может ли Эра получать системный вызов ассистента при заблокированном телефоне.

Результат на 2026-08-01:

- Эра выбрана системным помощником;
- VoiceInteractionService запускается;
- onReady подтверждён логом;
- при вызове помощника на заблокированном устройстве появляется экран ввода графического ключа;
- onLaunchVoiceAssistFromKeyguard пока НЕ подтверждён.

Последний диагностический лог:

event=onReady
screenInteractive=true
deviceLocked=false
keyguardLocked=false

Следующая задача:

исследовать границу Android/HiOS Keyguard → VoiceInteractionService и выяснить, возможно ли вызвать Эру до разблокировки устройства.

Целевая задача
Получить сценарий:
телефон заблокирован / экран погашен → вызов Эры → официальный ChatGPT Voice Mode → разговор без ручной разблокировки телефона.
Разблокировать устройство или обходить Keyguard не требуется. Нужна штатная работа голосового помощника при сохранении блокировки.
Что уже работает
На разблокированном телефоне цепочка практически собрана:
Эра → запуск официального ChatGPT → AccessibilityService → обнаружение элемента Voice → автоматический запуск Voice Mode.
Физический тест подтвердил: ChatGPT открывается, и примерно через несколько секунд Voice Mode запускается автоматически.
Если ChatGPT оставлен в фоне, открывается существующий чат. Если приложение выгружено, поведение может отличаться, но сам механизм автоматического запуска Voice подтверждён.
Тест 1. VoiceInteractionService и аппаратный вызов с Keyguard
Эра назначена системным цифровым помощником Android.
Реализованы:
EraVoiceInteractionService
EraVoiceInteractionSessionService
EraVoiceInteractionSession
Проверялся штатный callback:
onLaunchVoiceAssistFromKeyguard().
Результат: при аппаратном вызове помощника на заблокированном TECNO появляется экран графического ключа.
onLaunchVoiceAssistFromKeyguard() в полученных логах подтверждён не был.
После ручной разблокировки запускается Эра.
Предварительный вывод: HiOS не отдаёт стороннему системному помощнику нормальный аппаратный вызов через Keyguard тем способом, который мы проверяли.
Тест 2. Activity поверх Keyguard
Создавалась специальная тестовая Activity с разрешением отображаться поверх lock screen.
Цель была проверить:
заблокирован → вызов → Activity Эры поверх Keyguard.
Результат: Activity не появилась поверх блокировки. Система показала графический ключ. После ручной авторизации Activity/Эра появилась.
То есть одного showWhenLocked недостаточно, если запуск самой Activity задерживается системой до авторизации.
Тест 3. Таймер при заблокированном телефоне
Сделали отдельный эксперимент:
кнопка в Эре → таймер 10 секунд → пользователь блокирует телефон → по таймеру код пытается запустить Activity.
При заблокированном устройстве ожидаемое окно не появилось.
После ручной разблокировки появился ChatGPT, а затем автоматически запустился Voice Mode.
Это показало важное разделение:
логика Эры может инициировать действие, но вывод Activity ChatGPT задерживается Keyguard до разблокировки.
Тест 4. Termux как независимая проверка
Чтобы исключить ошибку именно в Эре, проверили прямой запуск официального ChatGPT через Termux:
am start -n com.openai.chatgpt/.MainActivity
На разблокированном телефоне команда нормально открывает ChatGPT.
Затем:
sleep 10; am start -n com.openai.chatgpt/.MainActivity
После запуска команды телефон блокировался.
Результат: под блокировкой тишина. После ручной разблокировки ChatGPT сразу появился.
Следовательно, проблема не специфична для нашего startActivity(): обычный внешний запуск ChatGPT также задерживается Keyguard.
Дополнительно через cmd package подтвердили обычную точку входа:
com.openai.chatgpt/.MainActivity
Очевидной публичной отдельной VoiceActivity обнаружить не удалось.
Ветка Termux пока закрыта.
Тест 5. VoiceInteractionSession
Создали минимальное визуальное содержимое собственной EraVoiceInteractionSession:
«ЭРА / VoiceInteractionSession работает»
Задача была проверить, сможет ли именно системная Voice-сессия, а не обычная Activity, появиться поверх Keyguard.
Результат: снова появился графический ключ. После разблокировки открылась Эра.
Следовательно, проверенная нами конфигурация VoiceInteractionSession тоже не дала видимого интерфейса до авторизации.
Тест 6. Звуковой сигнал из onLaunchVoiceAssistFromKeyguard()
Чтобы вообще исключить проблему отображения окон, Activity убрали из эксперимента.
В:
onLaunchVoiceAssistFromKeyguard()
добавили короткий звуковой сигнал.
Идея:
если callback выполняется под Keyguard, мы услышим сигнал независимо от возможности показать окно.
Результат: при аппаратном вызове на заблокированном телефоне сигнала не было.
После разблокировки запускалась Эра.
Это дополнительно указывает, что проблема находится раньше попытки показать Activity.

Сигнал перенесли непосредственно в:

Главный результат дня
Мы не доказали, что сторонний ассистент вообще принципиально не способен работать под Keyguard на Android или даже на HiOS.
Но для конкретного TECNO Camon 40 / Android 16 / HiOS 16.2 проверенный нами аппаратный путь ведёт себя так:
заблокированный телефон
→ аппаратный вызов сторонней Эры
→ HiOS требует графический ключ
→ только после авторизации управление фактически переходит Эре.
При этом обычный внешний запуск официального ChatGPT ведёт себя аналогично:
запрос запуска под блокировкой
→ ChatGPT не появляется
→ разблокировка
→ ChatGPT появляется
→ Accessibility может автоматически включить Voice Mode.
Поэтому завтра не стоит продолжать бесконечно менять Activity, showWhenLocked и звуковые сигналы вокруг того же аппаратного вызова. Эта ветка уже достаточно хорошо исследована.
Следующий этап лучше начать с поиска другого системного механизма, который способен получить событие и выполнить нужную цепочку до разблокировки, при этом конечная цель остаётся неизменной:
«Привет, Эра» → официальный ChatGPT Voice → телефон остаётся заблокированным.
И ещё важное: странный единичный onReady при deviceLocked=true сохраняем как наблюдение, а не как доказательство рабочего пути. Его происхождение пока неизвестно. �
